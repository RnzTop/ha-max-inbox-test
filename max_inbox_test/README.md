# Уведомления о входящих MAX

Это отдельный стенд Home Assistant для проверки локальной очереди на искусственных событиях. Рабочий сборщик реальной переписки пока не готов.

В тестовой веб-сессии MAX проверено получение текста. Два сообщения с одинаковым текстом отобразились отдельными входящими элементами. Между ними обнаружено фото, отправленное без подписи. После перезагрузки вкладки вход сохранился. Номер отправителя, устойчивый ключ сообщения и восстановление сессии при перезапуске браузерного процесса пока не проверены.

Очередь принимает события с устойчивым ключом из аккаунта, диалога и сообщения. Для первоначальной отметки старых событий предусмотрен режим baseline. При получении текста фото передаётся текст, при пустом сообщении указывается тип вложения. Номер включается только при наличии значения, предоставленного источником. После отправки карточки первое нажатие с совпадающим идентификатором карточки атомарно закрепляет сотрудника. Транспорт должен проверять, что нажатие пришло из заданной закрытой группы, прежде чем передавать его в очередь.

Если после отправки невозможно установить, принял ли MAX сообщение, запись остаётся в состоянии uncertain. Автоматическая повторная отправка могла бы создать дубль. Рабочей версии потребуется сверка такой записи с группой или решение оператора.

Проверка на искусственных событиях в этой папке:

    python3 -m unittest -v

Следующий этап — подтвердить устойчивый ключ нового входящего в тестовой сессии, включая повтор одинакового текста после перезапуска браузерного процесса. Позиция элемента в открытом диалоге для этого не годится. Затем можно подключить чтение, QR через защищённую панель HA и транспорт MAX для отдельной тестовой группы. Для кнопки нужно либо добавить обработчик в действующего бота через его существующий канал получения событий, либо использовать отдельного тестового бота. Два независимых обработчика событий на одном токене могут конфликтовать.

## Стенд Home Assistant

В этой папке есть устанавливаемое локальное дополнение **MAX — стенд уведомлений**. Оно использует отдельный идентификатор и открывается через Ingress HA. Дополнение показывает искусственные данные, не запрашивает токен, не открывает веб-сессию и не посылает сообщения.

Для установки скопируйте папку в каталог локальных дополнений HA, обновите магазин, установите стенд и нажмите «Открыть веб-интерфейс». Загрузите три тестовых события. Нажмите кнопку сотрудника и обновите страницу. После перезапуска повторно нажмите загрузку тестовых событий: список и ответственный сохранятся, повторные карточки не добавятся. Вне HA запустите `python3 demo.py ./demo.sqlite3 127.0.0.1 8099` и откройте http://127.0.0.1:8099/.

После закрытия прежней вкладки и открытия новой в том же браузере MAX снова показал тестовый диалог без повторного входа. Два одинаковых текста сохранили разные позиции в этом конкретном диалоге, фото осталось между ними. Стабильный идентификатор, который не зависит от позиции и подгрузки истории, в проверенной разметке не обнаружен. Полный перезапуск Chromium внутри дополнения и доставка в MAX остаются отдельными проверками.
